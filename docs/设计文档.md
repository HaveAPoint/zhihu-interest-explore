## 1. 产品是什么

在知乎专栏文章上盖一层原生风格蒙版，让读者用「选中文字 → 高亮追问 → 箭头层层分叉」的方式做兴趣探索。每一棵追问树的根，只挂到一门具体学科知识树上的一个节点。读的时候在原页；回看的时候在独立网页上看整棵学科树哪一块亮了，点一条记录就能跳回当时的文章和那棵树。

一句话定位：兴趣向的、强制具体的、挂在权威学科框架上的阅读追问。

服务对象是「读着玩、想把一篇文章读懂」的人，不是做跨学科深研的人。主题不鲜明或横跨多学科的文章，视为没有阅读价值或不属于本产品，不特殊处理。

---

## 2. 不可妥协的原则

主框架完整。全局知识树来自预备学科库。例子、解释、细节一律作为内容附着在已有节点上。新增全局节点是严格例外，必须由用户在树上亲自选位置，加入后标「个人补充」。Agent 不得自行往主框架塞节点。

求具体。没有高亮就不能追问。用户必须先指出「是这一句、这一个词没懂」。这是有意的摩擦，用来换思考，不是省事没做成。

一树一根一节点。一棵局部追问树只根植于全局树的一个节点，可以是任意层级，实际多半很深、很具体。点亮只发生在这一个绑定上。后续追问全部是这棵树的内容，不再点亮任何全局概念。子节点不继承父节点的点亮。

核心闭环只有四步：阅读、追问、自动保存、回看。熟练度是主观、次要的，只放在节点详情里供用户手改，不参与点亮、推荐、主流程。

克制。每条回答约 200 字。少用专业术语，按用户当前这条思路把事情讲明白。深度靠再高亮追问，不靠把单条回答写成教材。

原生。当前阅读盖在知乎原页面上，不把文章搬进自建阅读器。文章被删改导致锚点失效的问题，本版本不考虑。

## 3. 系统的三块

浏览器插件。只在专栏文章页 `zhuanlan.zhihu.com/p/*` 生效。负责：判定学科、选中开树、蒙版、高亮与箭头、局部树、删除、锚点恢复、跳到独立页的入口。

独立网页。全局知识树和探索记录的回看处。从一条记录可以跳回知乎原页并唤起对应的树。插件蒙版里只留一个入口按钮。

后端。知乎 OAuth 登录、数据落库、调用模型和全网搜索、加载学科 skill。插件和独立页共用同一份云端数据。

## 4. 核心对象

用户。用知乎账号登录。

具体学科。粒度必须是「认知心理学」「分布式系统」「Agent 应用开发」这一级，不允许「心理学」「计算机」。黑客松预备三棵：Agent 应用开发、认知心理学、分布式系统。一篇文章只判定一次学科，之后不重判、不回退。同文所有局部树都在这一棵学科树里找挂靠候选。

全局节点。学科树里的一个节点，有名字、别名、层级路径、一句定义。可被标记为「个人补充」（用户加的）或「生成」（整棵树是生成入库的）。节点有点亮状态，由「是否还有探索记录」推导，不是独立开关。

文章。一篇知乎专栏。保存：知乎文章 id、url、标题、tag、首段、判定出的学科。本版本不依赖正文长期不变，但开树时的引文文本要存下来，用来重返时匹配锚点。

局部树。属于一篇文章、一个用户。根节点尝试挂靠一个全局节点。状态是「已挂靠」或「待挂靠」。待挂靠不影响追问和保存，只是全局树暂时不亮。

局部节点。树上的一问一答。每个节点（根也算）都对应一处高亮：根对应原文选中，子节点对应某条回答里的选中。存：高亮原文、用户问题（可空）、LLM 短标题、回答正文、来源列表、创建时间。

探索记录。当且仅当局部树已挂靠时，在该全局节点下出现一条记录。一条记录 = 一棵局部树。显示：文章标题、根节点短标题、时间。点击 = 跳回该文章并展开这棵树。

## 5. 阅读时：从选中到一棵树

### 5.1 进入文章

用户打开一篇专栏。插件注入。LLM 依据标题、tag、首段直接判定具体学科并自动启用，页面上出现可改的小标签，例如「学科：Agent 应用开发」。用户可以点改，但默认不打扰。判定只发生这一次。

### 5.2 开树

用户在正文里选中一段文字，出现一个小按钮。点击后：

引文取选中文字所在的整段，段内高亮实际选中的部分。选中恰好是整段，就整段高亮。

蒙版打开。引文置顶。下方输入框。用户可以打字，也可以留空回车。留空按「解释这处高亮」处理。

正文里这段成为这棵树的锚点，带浅色标记。一篇文章有几棵树，正文里就有几处锚点。

不允许无选中的空提问，避免挂不到原文的孤儿树。

### 5.3 蒙版里怎么摆

局部树尽量固定在页面右侧。真正分叉、横向超过 1 的宽树，允许越界或挤压知乎原页布局。插件对页面 DOM 有完全控制权：可以给 body 加右侧留白，把正文挤到左边，也可以固定定位覆盖。不要用 Chrome Side Panel，宽度不够。知乎自己的顶栏和右侧推荐栏是实现时要单独让开或挤走的元素。

树上每个节点只显示 LLM 概括的短标题（约 6～12 字），不显示完整问答。完整问答在选中节点后于旁边展开。最新回答默认展开。

### 5.4 追问：强制高亮，层层箭头

要对某条回答追问，必须先在该回答里选中一段文字。不允许对整条回答空泛提问。这是强制思考。

高亮粒度：最短一个词，最长整条回答。不校验是不是完整句。

选中后可以打字，也可以留空发送。留空 = 「解释这处高亮」。

发出后：高亮保留，从高亮处画一条指向箭头，引出下一层回答。在哪条回答里高亮，就从哪里分叉。树可以分叉，不是单链。

### 5.5 单击和双击

单击节点：立即选中，展开这一问一答，树上高亮从根到该节点的路径。单击必须立刻生效，不能为了等双击而延迟。

双击节点：展开或收起它下面的后续追问；右侧同时切到从该节点往下的整条追问线。因为单击是双击的子集，先执行单击再叠加双击是安全的。

默认只展开当前正在追问的那条链，其他分支收起。

触屏没有双击。移动端用长按或节点旁小箭头代替。黑客松以桌面浏览器为准，移动端可以后做。

### 5.6 新追问挂在哪

在哪条回答里完成了高亮并发送，新节点就挂在那条回答下面。这是分叉的唯一方式。没有「先选中节点再在输入框里打字」的第二条路径，因为追问必须高亮。

### 5.7 重返已探索的文章

插件加载后，用已存的引文文本在正文里匹配，恢复所有锚点高亮。锚点旁一个小标记，带这棵树的节点数（例如「3」）。

蒙版默认不弹出。用户大概率是来重读的。点锚点标记，才打开对应的树，并展开到上次最后一条回答。

从独立页跳回来时，url 带参数，直接打开对应的树，跳过「先看原文」这一步。

## 6. 回答长什么样、怎么生成

### 6.1 篇幅和口吻

约 200 字，保持克制。这是兴趣探索，不是上课。尽量不用专业术语，根据用户已经问到哪一层，用简单准确的话讲明白。

结构上分得清两块：先写「原文说的是……」，再写「补充解释……」。不要混成一段让人分不清哪些是文章里的、哪些是模型加的。

### 6.2 上下文（每次生成回答时）

固定给模型这些：

原文全文。

这棵局部树的全部问答，包括兄弟分支。追问树会分叉，不是单链，模型必须看整棵树才不会跟自己打架。

当前这一处高亮文字。

同一篇文章的其他树不纳入。

用户在其他文章里的历史探索：只在生成根节点回答时以摘要注入，用来理解用户背景。之后的追问已经在具体语境里，不再塞历史。

历史探索只给模型看，绝对不要作为回答里的引用来源展示给用户。用户主动打开节点回看时，仍可看到原来的文章和问答。

### 6.3 联网

追问默认允许联网。不做「是否联网」的分流，用户不用选模式。

优先用已有知识库（预备学科框架的节点定义；根节点时还有历史摘要）。允许全网搜索。由 LLM 自己决定要不要搜、用哪些来源。优先官方文档、教材、原始资料。

外部来源统一放在回答底部折叠的「参考来源」，展开后是标题和链接。历史问答不列入。

### 6.4 短标题

每条回答生成时，LLM 顺带概括一个 6～12 字的短标题，作为树上的节点名。不要截断用户原问题。用户可在节点详情里改。

### 6.5 根节点的挂靠（只发生一次）

生成根节点回答时，LLM 在该文章所属学科树里找候选，最多三个，按匹配度排序，每个附一句匹配程度表述。建议用这三档：

「精确对应」—— 高亮所问的就是这个节点。

「上级概念，偏泛」—— 能挂，但还有更具体的子节点更合适，或问题比该节点更窄。

「相关但不同侧面」—— 沾边，不是一回事。

规则：

首选是「精确对应」：直接挂上。回答顶部小标签「已挂靠：××（精确对应）」。用户可点标签改成另外的候选或打开全局树自选。

首选不是精确对应：树保持未挂靠。标签「待挂靠：N 个候选」。用户点开选一个，或打开全局树手动加「个人补充」。未挂靠期间追问和保存照常，全局树不亮。

一个候选都没有：不弹「建议新增」的轻提示。直接把该学科的全局树展示给用户，让用户自己看加在哪里。加完标「个人补充」，主框架不动。

绑定之后，这棵树不再点亮任何其他全局节点。单个术语追问即使碰巧是另一个节点的名字，也不点亮它。用户想点亮那个概念，回到原文选中那个词，另开一棵树。

## 7. 点亮

点亮只发生在「局部树根节点 ↔ 全局节点」这个绑定上。

点亮状态由「该全局节点是否还有至少一条探索记录」推导。删掉最后一条来源，节点自动恢复未点亮。不要做第二套手动点亮开关。

子节点不继承父节点的点亮。父节点亮了，子节点该灰还是灰。

颜色：

未点亮：灰色。

自身被点亮：淡黄色。

自身被点亮，并且它下属全部子节点也被点亮：加一个亮金色小 tag。不要整块改成金色。一块小 tag 示意即可。

父节点（非叶）在叶子收起时，用「已点亮 n / N」小标和颜色深浅表达比例，让缩小看全貌时能看出哪片区域被碰过。这个比例统计的是该节点子树里被点亮的节点数，不是「继承」。

再次探索已点亮的节点：只增加一条探索记录，不自动改熟练度。

---

## 8. 删除

删任一局部节点，即删它和它的全部后代（局部断链）。删根节点 = 删整棵树。

蒙版内：长按节点，拖到屏幕底部删除栏。拖到删除栏本身已是刻意动作，蒙版内不再弹确认。

独立页探索记录列表：每条记录可删，效果是删整棵对应的局部树。这里是单击，保留一句确认。

删除后：原文对应锚点高亮消失。若这是该全局节点的最后一条探索记录，该节点自动恢复未点亮。点亮不在删除时「单独回退」，而是记录清零后自然灰掉。

## 9. 回看时：独立网页

### 9.1 职责划分

蒙版负责读的时候。独立页负责回看的时候。插件里只留一个入口按钮打开独立页。

从独立页点一条探索记录：跳到知乎原页（带参数），插件唤起蒙版并展开那棵树。

### 9.2 全局树怎么画

横向层级：根在左，逐层向右，同层纵向排列。画布可平移缩放。

所有非叶节点默认全部展开。叶节点默认收起，折在父节点里不单独铺开。

单击父节点：在它右侧原位展开这一组叶子，纯列表，已点亮的带淡黄色。再次单击收回。允许多个父节点同时处于展开叶子的状态。

右侧面板始终只放节点详情，不拿来列叶子。叶子要和兄弟、父节点留在同一视野里。

### 9.3 节点详情，只有两块

顶部：概念名。若是个人补充，带「个人补充」标记。旁边是可手动改的熟练度（旁路，不进任何自动流程）。

下面：探索记录列表。每条对应一棵根植于此的局部树，显示来源文章标题、根节点短标题、时间。点任一条跳回。

不放任何 AI 生成的概念总结。回看的核心是找回当时的思路，跳回原文比读脱离上下文的摘要有用。

## 10. 账号

登录默认绑定知乎账号，走知乎开放平台 OAuth。黑客松视为可获得权限。本版本不为邮箱 / GitHub 等兜底登录做设计。

插件跑在知乎页上，可以读到当前登录用户，用来和 OAuth 身份对齐，但登录动作走官方 OAuth，不走非官方逆向接口。

## 11. 学科库怎么进 Agent

预备学科库，以两层 skill 作为 agent 背景信息。

第一层常驻：学科大类 + 具体学科。例如「人工智能 → Agent 应用开发」「心理学 → 认知心理学」「计算机系统 → 分布式系统」。用于判定一篇文章该进哪棵树。判定本身用标题、tag、首段，不让用户从列表里选。

第二层按需：该具体学科下的知识树骨架。节点名、别名、层级路径、每节点一句定义。这是挂靠候选和匹配度表述的依据。

节点配套的权威正文如何加载（并入第二层还是再拆第三层），技术上待商榷，黑客松阶段不配节点正文。回答时靠模型知识 + 联网补足。

库里没有的学科：LLM 按权威资料生成骨架，用户确认后入库，整棵树标「生成」。本版本演示不走这条路径。

黑客松三棵树的骨架由 LLM 生成再人工过一遍。Agent 应用开发没有经典教材目录，骨架来源改为主流官方文档和公认课程大纲，生成时多一轮人工把关。

## 12. 界面文案（开发时按这个写，不要自己发挥）

学科标签：「学科：{具体学科名}」

已挂靠：「已挂靠：{节点名}（{匹配程度}）」

待挂靠：「待挂靠：{N} 个候选」

父节点计数：「{已点亮数} / {子节点总数}」

来源折叠标题：「参考来源」

亮金 tag 文案：「全亮」即可，不要写长句。

删除栏：拖到附近时显示「松手删除此节点及其后全部追问」。

独立页记录空态：「还没有从文章里走到这里。」不要卖萌，不要道歉。

回答里不要出现「作为 AI」之类的自我介绍。不要把历史问答写成「你上次问过」。

---

## 13. 视觉约定（给开发的最低必要量，不是视觉稿）

点亮淡黄色：用浅黄底，不要刺眼，不要整块金色。建议背景接近 `#FFF4C2`，文字仍用深色。

亮金 tag：小胶囊，背景接近 `#E6B422`，白字或深字，面积大约一个「全亮」二字。只出现在「自身亮且全部子节点亮」的节点上。

未点亮：灰色文字，无底色。

原文锚点高亮、回答内高亮：同一套浅黄高亮，和点亮色可同系，但高亮是文字背景，点亮是树节点底色，不要做成同一种形状以免混淆。

箭头：细、实线、从高亮块边缘指向下一层回答。不要装饰性曲线。

蒙版：不要做成厚重的暗色遮罩把原文盖死。原文仍在，右侧是树。挤压布局时原文变窄，不要消失。

独立页：浅色、宽屏、画布可拖。不要做成卡片墙。

## 14. 演示主线（验收用）

1. 用知乎账号登录。
2. 打开一篇 Agent 应用开发方向的专栏文章。
3. 页面出现「学科：Agent 应用开发」，可改但演示不改。
4. 选中一段文字，留空回车。
5. 蒙版打开，引文置顶并高亮，回答约 200 字出现。顶部「已挂靠：××（精确对应）」。树在右侧。
6. 在回答里高亮一个术语，留空或打几个字追问。箭头引出第二层。
7. 回到第一条回答，高亮另一句再追问，形成分叉。
8. 长按一个分支节点，拖到底部删除栏，该分支消失，另一支还在。
9. 点入口打开独立页。横向全局树上，被挂靠的节点淡黄色；若它还不是全亮，没有金 tag。它的父节点显示「1 / N」之类的比例。
10. 单击父节点，右侧原位展开叶子，亮的那片淡黄。

## 附录：Grillme 锁定条目对照

A 定位与范围：专栏文章；兴趣向；闭环为读 / 追问 / 自动保存 / 回看。

H 点亮：只绑根；不继承；淡黄 / 亮金小 tag；熟练度旁路。
