# 知乎兴趣探索 · 分工与架构（人话）

日期：2026-09-13  
给：作者本人 + 做 Agent 的队友  
产品规则仍以 [设计文档.md](设计文档.md) 为准。接口列表以 [开发文档.md](开发文档.md) 为准。本文只写「谁做什么、数据怎么走、一开始怎么用假数据」。

---

## 1. 软件长什么样

三块：

- **浏览器插件**：只在知乎专栏 `zhuanlan.zhihu.com/p/*` 上工作。划词、蒙版、高亮、箭头、局部树。文章不搬进自建阅读器。
- **独立网页**：回看全局知识树。用 React。
- **服务器**：登录、存数据、以后接模型。

本地为主：插件先把树存在自己电脑里，有网再传到服务器。独立页只看服务器，可以稍旧。

登录：只在独立页用知乎 OAuth。长期认的是知乎 `uid`（当字符串存），不是一小时过期的 token。token 过期也不踢登录。没登录时插件也能先探索，登录后再把本地树挂到这个 uid 上传。

---

## 2. 你做什么

插件、独立页、服务器上的登录和存取、本地存储和同步。

你要先定对外接口（开发文档第 3 节那些），并先打通 **假数据**。不要等队友的模型。

包括：

- 知乎 OAuth、session、用户表（主键是 `uid` 字符串）
- 文章、局部树、节点的增删改查
- 插件：选区、蒙版、锚点、箭头、删除
- 独立页：横向知识树、点亮、跳回专栏
- 本地写入 → 排队同步到云端；冲突以插件本地为准
- 调用 Agent 的那一层：**先写一个假实现**

不去做：模型、prompt、全网搜索、挂靠候选的智能匹配（根节点假数据可以写死 0～3 条候选）。

---

## 3. 队友做什么

只做 **Agent 逻辑**，放在同一仓库的 `server/agent/`。

他们实现三个能力（输入输出见下一节）：

1. 判定学科（标题 + tag + 首段 → 三棵里的一个 slug）
2. 生成根节点：短标题、补充解释、来源、最多 3 条挂靠候选
3. 生成追问：短标题、补充解释、来源（不再挂靠）

他们不管插件 DOM、OAuth、数据库、React 页面。

「原文说的是」**不是模型写的**，是你这边把用户选中所在的**整段原文**原样放进界面。队友不要编这段，也不要改写。补充解释才是当时那次的解释。

---

## 4. 你要不要给他们接口？要。先假数据。

要。否则他们不知道该接什么，你也没法先做插件。

分两层，别混：

**给插件 / 独立页的 HTTP**（你写、你守）：就是开发文档第 3 节。例如 `POST /trees`、`POST /trees/:id/nodes`。插件只打这些。假数据阶段这些接口已经能返回一棵完整的树，只是回答是写死的。

**给队友的内部约定**（你定形状，他们填实现）：服务器在处理上面两个 POST 时，调用 `server/agent` 里的函数。一开始这个函数返回假 JSON；队友之后换成真模型，**函数签名不要变**。

建议三个函数（名字可改，字段不要改）：

```ts
classifyArticle({ title, tags, lead }) 
  → { slug: "agent-app-dev" | "cognitive-psychology" | "distributed-systems" | null }

generateRoot({ article, tree, highlight, question, historySummary, disciplineSkeleton })
  → { title, extra, sources, candidates }

generateFollowup({ article, tree, highlight, question })
  → { title, extra, sources }
```

- `title`：6～12 字短标题  
- `extra`：补充解释，约 200 字，少术语  
- `sources`：`{ title, url }[]`，不要把用户历史问答当来源  
- `candidates`：仅根节点；`{ node_id, degree: "exact"|"broader"|"related", reason }` 最多 3 条；`node_id` 必须来自你传入的学科骨架  
- **没有 `original` 字段**。整段引文由你从 `anchor_paragraph` / 高亮原文填进 UI。

假数据阶段示例：

- `classifyArticle` 永远返回 `agent-app-dev`（或按标题关键词随便判一个）
- `generateRoot` / `generateFollowup` 用高亮文本拼一句「补充解释」，`title` 用高亮截到 12 字，`sources` 空数组，`candidates` 空数组（界面走「待挂靠 / 打开树手加」也行）或写死一条 `exact`

插件和独立页从第一天就当这些是真接口来接。队友就绪后只换 `server/agent` 内部，HTTP 不用改。

未登录时：插件可以不打需要登录的 HTTP，只写本地；假回答也可以先写在插件本地（或后台用同一套假函数）。登录后按队列上传。不要因为假数据就把「必须先登录才能划词」做死。

## 5. 仓库怎么分

```
plugin/          你：浏览器插件（content script 直接 DOM，不要 React）
web/             你：独立页（React）
server/          你：OAuth、CRUD、同步、调用 agent
server/agent/    队友：三个函数的真实现；你先放假实现
disciplines/     学科树 JSON（可先用假骨架）
docs/            只读
```

全 TypeScript。不要为 Agent 再开一个服务。

## 7. 这次相对原开发文档的修正（实现时按这个，不要悄悄改产品交互）

- 存储：已装插件时界面优先读插件本地；同步用整棵树 + 根 id + 整数 version，大的覆盖小的。不是「两边共用一份纯云端、插件不落本地」。
- 回答：`original` 改为原文整段直接引用，模型只出 `extra`。
- 登录：产品 session 长有效；知乎 token 短；身份键是 uid 字符串。
- 插件 UI 不用 React。

## 8. 本轮架构追问锁定（2026-09-13）

独立页从插件里的链接打开。第一次用在独立页走知乎 OAuth，把 `uid` 绑到本产品用户；之后同一 uid 不再当新用户。

服务器：腾讯云开发，环境已在本机登录。EnvId：`hackerson-d0g0z55d2fc446485`（上海，体验版）。人话：独立页和插件下载包放在云开发的静态网站上（一组网页文件）；登录、存树、调 Agent 走云函数（一段在云上跑的 TypeScript）。知乎 OAuth 回调填这个网站的地址。不要另开云主机。密钥只放云函数里。

数据：使用当前云开发环境已开通的 PostgreSQL，不再使用文档数据库方案。用户、session、文章、局部树、局部节点、个人补充节点和熟练度分表存储。`tags`、`sources`、`match_candidates` 等灵活字段使用 `jsonb`。插件本地仍按整棵 JSON + 整数 `version` 保存；同步到服务器后，由后端在一个 PostgreSQL 事务中更新树与节点。

学科骨架：仓库里的 JSON 文件是真相源，黑客松期间不改。部署时读进库或云函数读文件。需要追加的节点不改这三份文件，另写一张「额外节点」表，用父节点 id 定位挂在哪。Agent 匹配候选只看骨架，不把额外节点当主框架。

语言：全 TypeScript。

换账号：本版本不考虑。真发生了，本地数据按 uid 分开放，不要合并。

同步：不做按节点差量。一棵局部树整棵上传；用根节点稳定 id 定位。子节点只存父节点 id，收到整棵包后重新长成树。

读：已装插件时独立页和蒙版都优先读插件本地。

写 / 推送：每棵局部树一个整数 `version`，本地每次改动 +1。同步时比两边 version，大的整棵覆盖小的。同 version 视为已对齐，不再推。不要按节点做版本。

独立页（已登录）每次动手改之前先 `GET` 云端这棵树：和当前所见不同就先套用云端，再允许改。不要轮询。不要墓碑行。云端该用户的树列表里没有这个根 id = 已删除，插件丢掉本地那棵，不要用更高 version 救活。离线期间本地还在长、另一头已删：以上线时云端没有为准。

熟练度只在云端全局节点上，不进局部树 version，不进插件缓存。

同号冲突（两边都从同一 version 各 +1）：以插件本地整棵盖云端。唯一例外仍是删除：云端列表没有这棵树，丢掉本地，不要救活。独立页改前先 GET，正常抢不到同一号。

海选没有现场演示。插件按下载包交付。

提交主链接是公网独立页，不是 zip。不另做仿专栏页：划词和长新节点只发生在真的 `zhuanlan.zhihu.com/p/*` + 插件。未登录不挡在门外。

未登录时独立页的数据来源分两档：

- 已装插件：独立页检测到扩展后立刻切到完整体验，不再用示例树冒充探索记录。向扩展要本地树（`externally_connectable`），挂到全局骨架上。点记录跳真专栏 URL，插件在那页打开蒙版。本地还空时：骨架全灰 +「打开这篇示例专栏」真链接，不要填假点亮。安装引导和效果录屏收起来，不当主界面。同步仍先展示本地，后台用树的 `version` 和云端比，较大的一侧整棵覆盖较小的一侧。
- 未装插件：扩展桥不存在。独立页展示写死的已点亮示例骨架、安装三步、「打开这篇示例专栏」（真知乎 URL，但没插件划不出树），以及一段「安装之后的效果」录屏（划词 → 蒙版 → 分叉 → 点回知识树）。树上记录点回去也是真专栏 URL。不是仿专栏阅读器。

登录后切到云端真实数据。真插件和知乎登录写成「完整体验」，不是门禁。插件不会下载后自动启动，必须打开一篇专栏才注入。不要把「先登录知乎」做成第一步。`designs/zhihu-explore/` 只当对照，不是提交物。
